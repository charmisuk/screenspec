# 적용 모드

> 세 가지 모드와 앱에 심을 때의 저장 경로. 개요는 [README](../README.md#적용-모드).

| 모드 | 대상 | 붙이는 법 |
|---|---|---|
| `wrap` (기본) | 단일 HTML 프로토타입 | [README 직접 적용](../README.md#직접-적용) 그대로. 기기 폭 시뮬레이터(모바일 360×800 · PC 1920×1080 · 손잡이로 끌기) 포함 |
| `overlay` | React · Next · Vue 등 | DOM을 건드리지 않고 얹기만 한다. 화면 구분은 라우트로 |
| `frame` | 프레임워크 앱 + 폭 확인·겹침 회피 | 앱을 액자(iframe)에 넣고 뷰어는 밖에. 설명 패널이 앱을 덮지 않고, 모바일/PC 전환이 앱의 미디어쿼리를 실제로 발화시킨다 |

wrap·overlay는 자동 감지되지만 명시가 안전하다(`frame`은 명시 전용).

**창에 안 들어가면 저절로 줄여서 보여준다.** `PC 1920×1080`은 통계적 최다이지 내 모니터가 아니라서, 노트북에서 열면 프레임이 창을 넘고 **앱이 화면에 고정해 둔 패널·버튼이 창 밖에 놓인다**(밀면 보이지만, `focus()`·`scrollIntoView`·폼 검증의 「첫 오류로 이동」은 그리로 못 간다). 그래서 넘칠 때는 **크기를 그대로 둔 채 배율만** 줄인다 — 시트는 여전히 1920이라 앱의 미디어쿼리도 그대로다. 지금 배율은 크기 옆에 `1920×1080 · 73%`로 적힌다. **넉넉한 모니터에서는 아무 일도 일어나지 않는다**(100%면 아무 말도 안 한다).

**누를 것은 없다.** 한때 이 자리에 「자동」과 「맞춤」 두 버튼이 있었지만 걷어냈다 — 둘 다 같은 호소에 대한 답이었고, 줄여서 잃는 것이 없으니 판단이 아니라 규칙이기 때문이다. **프로토타입 모드와 화면정의서 모드가 같은 규칙**을 쓴다. 그 사이 크기가 필요하면 **프레임 가장자리를 끌면 된다**(끈 크기는 창을 줄여도 지켜지고, 프리셋을 누르면 돌아온다).

**폰처럼 좁은 화면에서는 상단 바가 접힌다** — 「모바일 | PC」 폭 시뮬레이터는 숨고(자기 화면이 곧 기기라 잴 것이 없다), 저장·설명 복사·내보내기는 오른쪽 **⋯** 안으로 들어간다. 저장할 것이 남아 있으면 ⋯ 위에 점이 뜬다.

**앱(`overlay`·`frame`)에서는 저장 경로가 다르다.** 단일 HTML 은 «문서 = 파일» 이라 그 파일에 바로 되쓰지만,
앱은 주소로 열리므로 브라우저에 쓸 파일이 없다. 정의가 사는 소스 파일이 어디인지는 **호스트만 안다.**
그래서 저장을 호스트에 넘기는 훅을 단다 — 안 달면 편집은 되고 되쓰기만 막힌다.

```js
window.SCREENSPEC = {
  mode: "overlay",
  save: { async write(blockText) {           // 라이브러리가 바뀐 설정 블록 텍스트를 넘긴다
    const r = await fetch("/api/screenspec", { method: "POST", body: blockText });
    if (!r.ok) throw new Error(await r.text()); // 실패는 throw — 저장 표시가 되돌아간다
  } },
  screens: [ /* ... */ ]
};
```

받는 쪽(개발 서버)은 넘어온 텍스트로 정의 소스 파일을 바꾸면 된다. 자세한 것은 [저장을 호스트에](config.md#저장을-호스트에-save).

```js
window.SCREENSPEC = {
  mode: "overlay",
  screens: [
    { id: "S-01", name: "대시보드", path: ["대시보드"], route: "/", specs: [] },
    { id: "S-09", name: "이용자 명단", path: ["이용자", "명단"], route: "/members", specs: [] }
  ]
};
```

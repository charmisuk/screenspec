# 사이클 기록 (회고 원료)

## #36 온보딩 인터뷰 + style
- `style` 은 라이브러리 설정이 아니라 **AI 가 읽는 계약**이라 「검증만 하고 렌더는 안 바꾼다」가 규칙이 됐다. lint 의 필드 커버리지 검사가 이걸 그냥 통과시켜서(문서에 적기만 하면 됨) 「동작 없는 필드」를 막아주진 못한다. 회고에서 볼 것.
- 프로토콜 라우팅대로 메인 세션 직접 처리(≤40줄). 실제 21줄. 맞았다.

## #37 편집 모드 — 실측 먼저
- 기획서가 「파일 접근 API 의 file:// 지원 범위를 구현 첫 주에 실측하라」고 못박아 뒀다. 계획 전에 쟀다.
- 결과: `file://` 에서도 `showOpenFilePicker`·`showSaveFilePicker` 가 **존재**하고 `isSecureContext === true`,
  헤드리스가 아닌 실제 창에서는 **피커가 실제로 열린다**(사람 클릭을 기다리며 멈춤). `SecurityError` 로 원본이
  거절되지는 않는다 → 「file:// 라서 못 쓴다」는 아니다.
- 다만 **자동 검증이 불가능**하다: 피커는 CDP 로도 못 채운다(이 크롬 빌드에 `Page.handleFileChooser` 없음).
  → 설계 결론: **순수 로직(직렬화·블록 교체)과 브라우저 껍데기(피커·핸들)를 분리**한다.
    순수 로직은 e2e 로 두들기고, 피커 경로는 사용자 QA 항목으로 넘긴다.
- 프로토콜 라우팅은 「>40줄이면 opus 서브에이전트」지만 이번 세션은 서브에이전트 사용이 막혀 있어 메인이 직접 했다.
  프로토콜이 든 근거(서브에이전트는 컨텍스트를 처음부터 다시 읽어 비싸다)는 이미 전 맥락을 쥔 메인에는 반대로 작용한다.
  회고에서 「라우팅 기준에 *메인이 이미 맥락을 쥐고 있으면* 예외」를 넣을지 볼 것.
- 빌드가 두 번 죽었다. 라이브러리 소스에 **스크립트 종료 태그**와 **HTML 주석 여는 표시**가 들어가면
  인라인 산출물이 통째로 깨진다(`<script>` 안에서 파서가 escaped 상태로 빠져 닫는 태그를 못 본다).
  종료 태그는 `scripts/inline.js` 가 이미 막고 있었는데 여는 주석 표시는 안 막고 있어서,
  같은 종류의 가드를 3줄 더 넣었다(계획 밖 변경 — dev.evidence 에 사유를 적었다).
  회고 질문: lint 가 잡아야 할 일 아닌가? 지금은 인라인 빌드를 돌려야만 드러난다.
- e2e 를 짜면서 내 단정이 틀린 게 한 건 있었다. 직렬화는 키 순서를 **일부러** 정규화하는데
  (「고친 줄만 바뀐 파일」을 내려면 그래야 한다) 왕복 검사를 `JSON.stringify` 문자열 비교로 써서 FAIL 이 났다.
  왕복은 «값» 기준으로 보고, 순서 고정은 별도 케이스로 따로 못박는 게 맞았다.

## #34 인쇄 · PDF
- lint 의 「Screen·Spec 필드」 추출기가 `o.xxx`·`x.xxx` 같은 **아무 지역 변수의 속성 접근**을 설정 필드로 읽는다.
  이번에 인쇄 옵션(`o.markers`)이 걸렸고, #37 에서도 `x.text()` 가 걸렸다. 두 번 다 변수명을 바꿔 피했다 —
  검사가 옳은 일을 하려다 애먼 것을 잡는 셈이다. 회고에서 추출 범위를 좁힐지(예: `spec.`·`sc.` 만) 볼 것.
- 인쇄 검증은 클래스만 세지 않고 `emulateMedia({media:"print"})` 로 **실제 인쇄 미디어를 켜서** 봤다.
  `@media print` 안의 규칙은 그렇게 하지 않으면 한 줄도 검증되지 않는다. `page.pdf()` 로 산출물까지 만들어 봤다.
- 「복제하지 말고 옮긴다」가 이 건의 핵심이었다. 앱 DOM 을 복제하면 상태·스크립트를 잃는데,
  옮기기는 모드 전환이 이미 쓰던 동작이라 새 위험이 아니었다. 되돌리기는 e2e 가 인쇄 전후를 비교해 못박는다.

## #38 개발 정의 레이어
- lint 오탐이 **이번 사이클만 세 번**이다 (`x.text` · `o.markers` · `x.setAttribute`).
  「Screen·Spec 필드」 추출기가 `s|sc|spec|next|o|x|current|cur|sc2` 뒤의 아무 속성 접근이나 잡는데,
  `o`·`x` 는 흔한 콜백 인자 이름이라 필연적으로 걸린다. 세 번 다 변수명을 바꿔 피했다 —
  즉 **코드가 검사에 맞춰 휘고 있다.** 회고 안건: 접두사를 `spec.`·`sc.` 로 좁히거나 SKIP 에 DOM API 를 채우기.
- 필터를 CSS 전용으로 짠 것이 수용 기준(「숨김이 마커·경고에 부작용을 주지 않는다」)을 **설계로** 만족시켰다.
  모델을 안 건드리면 부작용이 「없도록 고친 것」이 아니라 「생길 수 없는 것」이 된다. 검사보다 구조가 싸다.
- 레이어로 줄을 걸러 그리면서 `di`(원래 배열 인덱스)를 그대로 실은 것이 편집 모드와의 접점이었다.
  걸러진 순번으로 썼으면 «가운데 개발 줄을 고치면 엉뚱한 기획 줄이 바뀌는» 버그가 났을 것이다.
  e2e 가 배열 가운데를 고쳐 앞뒤가 그대로인지 확인한다.

## 🔧 이미 고친 것 (lint 갱신 — 프로토콜 2단계 「lint 질문」의 답)

**1. 인라인 빌드를 깨뜨리는 두 글자열을 lint 가 잡는다.**
라이브러리 소스에 스크립트 종료 태그나 HTML 주석 여는 표시가 있으면 자체 완결 파일이 통째로 깨진다.
`<script>` 안에서 HTML 파서가 escaped 상태로 빠져 닫는 태그를 못 보기 때문이다.
이번 사이클에 **두 번** 죽었는데, e2e 는 「인라인 부팅 실패」라는 **먼 증상**으로만 알려줘서 원인을 찾는 데 시간이 들었다.
→ `tests/lint.js` 18번 검사 추가. 줄 번호까지 짚는다. 음성 테스트로 검증했다 —
   미끼를 넣으면 `FAIL … 줄 [1]`, 빼면 통과.

**2. 설정 필드 추출기의 오탐을 없앴다.**
「Screen·Spec 필드」 검사가 `o.`·`x.` 뒤의 아무 속성 접근이나 설정 필드로 읽었다.
`o`·`x` 는 흔한 콜백 인자 이름이라 `x.text()`·`o.markers`·`x.setAttribute()` 가 걸렸고,
**이번 사이클에만 세 번** 변수 이름을 바꿔 피했다. 즉 **코드가 검사에 맞춰 휘고 있었다.**
→ 실측했더니 `o`·`x` 의 고유 기여는 **0개**였다(19개 필드가 나머지 접두사로 전부 잡힌다).
   검사력 손실 없이 오탐만 사라지므로 두 접두사를 뺐다.

## 💡 통찰 (프로토콜 변경 불필요 — `learnings.md` 후보)

**부작용은 「없도록 고치는」 것보다 「생길 수 없게 짜는」 게 싸다.**
#38 의 수용 기준이 「필터의 숨김이 마커·경고에 부작용을 주지 않을 것」이었다.
필터를 CSS 두 줄로 짜서 모델을 아예 안 건드리게 하니, 부작용이 **구조상 불가능**해졌다.
검사로 막았다면 앞으로 계속 지켜야 할 규칙이 됐을 것이다.

**자동으로 검증 못 하는 경계를 미리 재면 설계가 갈린다.**
#37 은 기획서가 「파일 접근 API 의 file:// 지원 범위를 첫 주에 실측하라」고 못박아 뒀다.
계획 전에 쟀더니 「막혀 있지는 않은데 **피커는 자동 조작이 불가능**」이었다.
그래서 되돌리는 쪽(직렬화·블록 교체)을 DOM 모르는 **순수 함수로 떼어** 브라우저 없이 검증되게 하고,
피커만 사용자 QA 로 넘겼다. 재보지 않았다면 「저장 전체가 테스트 불가」로 뭉뚱그렸을 것이다.

**`@media print` 안의 규칙은 인쇄 미디어를 켜지 않으면 한 줄도 검증되지 않는다.**
`emulateMedia({media:"print"})` + `page.pdf()` 로 산출물까지 만들어 확인했다.

**걸러서 그릴 때는 원래 인덱스를 실어야 한다.** (#38)
레이어로 줄을 걸러 그리면서 걸러진 순번을 썼다면, 가운데 개발 줄을 고칠 때 엉뚱한 기획 줄이 바뀐다.

## ➕ 프로토콜 개선 — 반영 완료 (issue-cycle.md v1.1 → v1.2)

**1 · 「실측하라」고 적힌 것은 계획보다 먼저 잰다** (G1 에 반영)

이번에 #37 은 실측 결과가 **설계를 갈랐다**. 계획을 다 쓴 뒤에 쟀다면 계획을 다시 썼을 것이다.

**2 · dev 라우팅에 「맥락 보유」 예외** (G2 에 반영 — 원안보다 좁게)
프로토콜 v1.1 은 「40줄 넘으면 서브에이전트」다. 근거는 「서브에이전트는 컨텍스트를 처음부터 다시 읽어 비싸다」인데,
**이미 전 맥락을 쥔 메인**에는 그 근거가 거꾸로 작용한다. 이번 사이클은 셋 다 메인이 직접 했고 되돌림이 0회였다.
→ 원안은 「맥락을 쥐고 있으면 줄 수와 무관하게 메인이 직접」이었으나, 그대로 넣으면 **메인이 계속 다 하다가 컨텍스트가 터지는** 반대 실패로 간다.
   조건을 셋으로 좁혔다: ①맥락 보유 ②쪼갤 수 없는 한 덩이 ③컨텍스트 여유. 그리고 «서브에이전트로 보내야 하는 경우» 를 나란히 적어
   예외가 「메인이 편하니까」로 쓰이지 않게 했다.

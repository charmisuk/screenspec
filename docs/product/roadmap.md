# 제품 로드맵

ScreenSpec 을 라이브러리(오프라인·무료)에서 클라우드 제품으로 키우는 계획의 단일 출처다.
전략 논의의 결론만 담는다 — 근거와 과정은 대화 기록·아티팩트에 있다. 가격은 전부 **제안값**이며 결제 붙이기 전에 확정한다.

> 상세기획: [Phase 0 (라이브러리)](phase0.md)

## 방향 한 줄

**오프라인에서 반하게 하고, 클라우드에 얹고, 기업에 판다.**
옵시디언 구조를 따른다 — 로컬 파일이 원본이고, 앱(라이브러리)은 영원히 무료이며, 파일이 못 하는 부가 서비스만 유료다.

유료선 한 문장: **혼자·오프라인은 전부 무료 — 클라우드에 두는 순간 소액, 두 번째 사람이 쓰는 순간 기업.**

## 플랜 (제안)

| 플랜 | 가격(제안) | 들어가는 것 |
|---|---|---|
| **Free** | ₩0 | 라이브러리 전부 — 붙이기·확인·**편집 모드**·인쇄(PDF)·레이어 형식. 공유물엔 Made with 배지 |
| **Personal** | ₩3,900/월 · 연 ₩39,000 | 클라우드 저장 · 버전 · 공유 링크 · 화면별 PNG · 배지 제거 |
| **Pro** | ₩9,900/월 · 연 ₩99,000 | Personal + **읽기 API + MCP**(자기 문서 한정) + 한도 상향 — 개인이 클로드 코드 등으로 자기 워크플로를 자동화한다 |
| **Team** | 좌석제 (Phase 2 에서 확정) | 역할별 동시 작성(개발 정의) · 핀 코멘트(게스트 무료) · 일괄 내보내기 · Confluence/Notion 연동 · 쓰기 API · 권한 |

- 개인이 투 티어인 이유: Pro 가 기업 API 의 베타 테스터가 된다 — MCP·API 수요를 기업 세일즈 전에 개인에게서 검증한다.
- 연결제를 기본으로 민다. PG 수수료·환불 운영을 생각하면 월 소액보다 연 단위가 낫다.
- 게스트·뷰어는 어느 플랜에서든 무료·무제한 (카테고리 표준).

## 사용자 여정

| 단계 | 사용자가 하는 일 | 제품이 하는 일 | 어디서 |
|---|---|---|---|
| 1 | 처음 붙일 때 세팅 | 온보딩 인터뷰 → `style` 설정 저장 | 오프라인 (0-1) |
| 2 | AI 에게 초안을 쓰게 한다 | SKILL.md + `style` + 프로토타입 HTML 을 읽고 작성 | 오프라인 |
| 3 | 직접 고친다 | **편집 모드** — 코드를 안 보고 패널에서 수정, 파일로 저장 | 오프라인 (0-2) |
| 4 | 개발 PM 이 개발 정의를 쓴다 | 레이어 형식(0-4) → 동시 작성은 Team | 형식은 오프라인, 협업은 온라인 |
| 5 | 화면별로 뜯어 올린다 | 인쇄·PDF(0-3, 오프라인) / PNG(온라인) — 마커 유무·표·레이어 선택 | 둘 다 |
| 6 | 프로토타입을 갈아끼운다 | 정의서는 항목 번호로 이어받는다 | 온라인 |
| 7 | 회사가 정의서를 찾아본다 | 검색 + REST API + MCP | 온라인 (기업) |

## 결정 기록

**D1 · AI 초안은 학습이 아니라 지시서다.** 모델을 학습시키지 않는다. 초안 = SKILL.md(작업 지시서) + `style` 설정(온보딩 답) + 프로토타입 HTML, 세 입력을 읽은 LLM 호출 1회다. 오프라인에서는 사용자의 AI 가 그걸 읽고, 온라인에서는 우리 서버가 같은 지시서로 호출한다. 취향이 `style` 에 쌓이므로 겉보기엔 「배운 것처럼」 동작하지만 실체는 매번 설정을 다시 읽는 것이다. 이후 수정은 사람이 하고, 재생성하지 않는다.

**D2 · 개발 정의는 탭이 아니라 인라인 레이어다.** 항목 행 **안에** 「개발」 블록으로 붙인다(하위 요소 1a·1b 와 같은 들여쓰기 문법, 다른 보더 색 + DEV 태그). 패널 상단에 필터 칩(전체·기획·개발). 탭으로 가르지 않는 이유: 개발 정의는 기획 정의를 **보면서** 쓰는 글이고, 실무 화면정의서도 한 표에 나란히 적는다. 항목에 안 붙는 화면 공통 정책은 화면 헤더 아래 공통 블록 하나.

**D3 · 정보 구조는 「제품 폴더 1뎁스 + 경로 라벨」이다.** 계층은 계정 → **제품** → 문서 → 화면. 폴더는 제품까지만 만들고, 그 아래는 폴더 대신 이름에 경로를 부여한다 (`Ctrl.room > 이용자관리 > 유저관리`). 근거: ① 라이브러리의 `screen.path` 배열과 1:1 — 업로드만 하면 트리가 저절로 생기고 마이그레이션이 없다 ② 재구성이 이름 바꾸기라 링크가 안 깨진다 ③ 폴더 미로를 피하고 검색·필터가 1차 탐색이 된다 ④ 커지면 경로 첫 단계를 그룹 헤더로 렌더하면 된다 — 나눠 보이는 **뷰**는 언제든 추가할 수 있고 저장 구조는 평평하게 유지한다. URL 은 `/{계정}/{제품}/{문서}` + `#화면ID`.

**D4 · 개인은 투 티어다.** Personal(클라우드) / Pro(+ API·MCP). 위 플랜 표 참조.

**D5 · 안 하는 것.** 실시간 동시편집(버전 기록 + 항목 잠금으로 충분) · 매 수정마다 LLM 재생성(초안 1회뿐 — 변동비를 바닥에 붙이는 구조의 전제) · 광고 CPM 을 주 수입으로 삼는 것(브랜딩 제거가 결제 동기, 광고는 붙이면 덤) · MVP 에서 git 을 저장소로 쓰는 것(내보내기 목적지로만).

**D6 · 내보내기 포맷 우선순위.** PNG(컨플·노션·티켓·PPT 에 다 붙는다) 1순위 — 단 브라우저 의존성 0 캡처는 신뢰도가 낮아 **오프라인은 인쇄(PDF)가, PNG 는 온라인 서버가** 담당한다. Markdown 표는 PNG 에 동봉, Confluence 페이지 생성은 기업 단계. 일괄 내보내기는 뒤로 미루고 유료로 걸 수 있다.
